Background

The BannerWise pattern

Banner Health — a 33-hospital system — built a Claude-powered oncology chart review assistant that processed over 1,400 pages of real patient notes in a pilot, cutting pre-visit chart review from roughly eight hours per patient to minutes. That system is behind a clinical firewall. This project replicates the same workflow architecture on synthetic data: the pipeline can be demonstrated, measured, and honestly evaluated without any patient privacy constraint.

The question this project answers is not "can Claude summarize text" — that's settled. It's whether the extraction is accurate enough, at the right field granularity, with an honest evaluation methodology, that a clinician could actually trust it. That's a harder bar.

Data

Synthea mCODE STU2 synthetic patient records, breast cancer module, ten-years-of-history depth (MITRE, 2022). FHIR R4. Fully synthetic — no data use agreement, no credentialed-access wait. 1,090 patients downloaded; 1,088 confirmed as breast cancer–positive via condition filtering; 50 sampled (seed=42, reproducible) for the eval set.

Scoring design

Fields where ground truth itself is genuinely unknown are excluded from scoring — not counted as a miss. Penalizing the model for correctly returning "unknown" on a chart with no underlying data measures the dataset's gaps, not the pipeline's accuracy. Free-text fields use fuzzy word-overlap matching. List fields (treatments, comorbidities) use precision/recall with fuzzy item matching.

Engineering

Six bugs found and fixed

Documented deliberately. A project with honestly disclosed engineering problems is more credible than one that hides the debugging process.

  • Multi-primary-cancer patients broke diagnosis selection. Some patients in this dataset carry two or three simultaneous primary cancer diagnoses (prostate + breast + lung). The parser grabbed whichever cancer condition appeared first in the FHIR bundle — not necessarily breast cancer — cascading into wrong stage and biomarker results for those patients. Fixed with a breast-specific condition selector.
  • Stage group silently failed for all 50 patients. This dataset's stage text is an AJCC label format ("Stage 2A") — Arabic numeral plus letter — not Roman numerals. The original derivation only searched for Roman-numeral substrings, which never matched, so stage_group defaulted to "unknown" across the entire eval set. Fixed with an explicit Arabic-to-Roman AJCC mapping. Claude had already been extracting the correct stage independently; the ground truth was the bug.
  • Clinical TNM stage cannot be validated here — a finding, not a failure. Ground truth's stage field contains an AJCC label, not real T/N/M categories at all. Excluded from headline accuracy claims rather than reported as a 0% extraction failure.
  • Diagnostic procedures were misclassified as surgical treatments. MRI and biopsy procedures were matched as "surgery" because they mentioned the breast. Fixed by excluding known diagnostic-procedure keywords.
  • Treatments recall was structurally unfair to the model. Synthea logs each medication administration as a separate FHIR record — one patient's ground truth listed the identical chemotherapy injection eight times. Claude correctly consolidated these into one summary entry with a cycle count. The eval was penalizing the model for being right. Fixed by de-duplicating ground truth before scoring; recall more than doubled (0.17 → 0.40) on the affected patient.
  • Comorbidity matching was too literal. Exact substring matching couldn't bridge reworded clinical phrasing ("Obesity (BMI 30+)" vs "Body mass index 30+ - obesity (finding)"). Switched to fuzzy word-overlap matching; precision/recall rose from 0.0/0.0 to 0.5/0.5 on the affected patient.
Limitations

What this is not

Synthetic data only

Synthea generates realistic-but-artificial records. No validation on real clinical charts.

Not a clinical decision system

Decision support prototype only. Not intended for use in clinical care settings.

Dataset gaps are real

~30% of patients lack biomarker or staging data — a Synthea characteristic, documented as a finding rather than an error.

Azure comparison deferred

The provider-adapter architecture supports dual-provider comparison; Azure OpenAI evaluation hit a connection error and was deferred.

Final re-run pending

Three scoring fixes verified on spot-checked patients; full 50-patient re-run deferred due to API budget constraints. Stated plainly, not hidden.

Single cancer type

Breast cancer module only. Findings should not be generalized to other oncology populations without further validation.
